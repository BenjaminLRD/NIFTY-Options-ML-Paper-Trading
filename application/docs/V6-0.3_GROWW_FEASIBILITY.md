## 2. Not established
1. **Your plan.** The documentation says live data needs a paid plan. Which plan your account holds is not visible to the assistant, which did not assume it. If it is Free Trial, the live-data and option-chain endpoints are documented as outside it.
2. **Whether those endpoints are actually blocked** on your account, and what error they return. The documentation gives no entitlement error format.
3. **Whether quotes are real-time or delayed.** No page states a delay, and no response field marks the data as real-time or delayed.
4. **Quote time.** The quote response has `last_trade_time` only, which is the time of the last trade, not the time of the quote. For a thinly traded option it can be old while the bid/ask is current. The option-chain response has no timestamp at all.
5. **Depth** beyond the one level shown in the example; **NIFTY option symbols** in the instrument file; **use restrictions** in Groww's terms.

## 3. Why the assistant stopped
- The free plan is documented as excluding the required endpoints, and you told the assistant not to assume or buy a plan.
- Even on a paid plan, the documented REST responses cannot support the dashboard's `LIVE` label or the V6-0.1 eligibility boundary on their own:
  - there is no field saying "this is real-time", so `LIVE` could only be claimed by assumption;
  - `last_trade_time` is not a quote timestamp. Using it as `Quote.ts` would wrongly reject good illiquid quotes, and using our receive time would claim freshness the provider has not stated;
  - the option chain has no bid/ask, so it can show prices but cannot be a fill source.
- A working adapter would also need outbound HTTPS, which the current structure tests forbid. That change should be made deliberately, not as a side effect.

4. Check Groww's terms for any limit on displaying or storing API market data.

## 5. Proposed minimal adapter interface (design only, not implemented)
- A provider keeps the V6-0.2 shape `provider(now) -> Snapshot | None`, and a new provider module is the only place that knows Groww. A failing call returns `None`, so the dashboard shows `UNAVAILABLE`; it never falls back to the synthetic provider (already tested).
- Each snapshot carries: `source` (`GROWW_REST_QUOTE`, `GROWW_REST_OPTION_CHAIN`), `kind` (`SIMULATED`, `LIVE`, `DELAYED`, `UNVERIFIED`), `received_at` (our timezone-aware clock), `provider_time` plus `provider_time_meaning` (for example `LAST_TRADE_TIME`), and the endpoint name. Raw payloads are not stored in logs.
- `LIVE` is assigned only on a documented real-time marker (none exists today); `DELAYED` only if Groww states a delay. Anything else is `UNVERIFIED`, shown without being called live and never passed to `require_fillable`. `STALE` and `UNAVAILABLE` keep their V6-0.2 meaning.
- To feed the eligibility boundary a quote would need a true quote time, or a rule you approve in advance (for example, bid/ask accepted only if its depth changes within N seconds across two polls). That rule is a design decision, not something to guess.
- Credentials: read the daily access token from a local environment variable. This avoids handling the API secret or the token POST, and the token never appears in tracked files, logs, errors or HTML. Calls would be GET-only to `api.groww.in`, with a test that rejects any order path.
- Tests use recorded fake JSON only: authentication and entitlement failures, missing fields, bad or non-numeric prices, crossed and locked bid/ask, naive or future timestamps, stale data, and source labelling.
