# V6-0.4 record: application hardening and demo readiness

Everything below was executed in this milestone unless it says otherwise. Invented data only; no provider, credentials, network or real orders; the V5.1 research folder, its frozen protocol and `data/paper_state/` were not touched (checked: ML folder still 425 files with none modified; saved account file hash unchanged).

## Bugs found and fixed

| # | Found by | Problem | Fix |
|---|---|---|---|
| 1 | Starting the real server against a replay saved by V6-0.3 | `/ml` raised `KeyError` and the browser got an **empty reply** (no page, no message) | Saved summaries are validated (format version, required fields, labelled as invented data with no provider); an unreadable one is listed with a reason, never rendered. The server also turns any unexpected page failure into a plain 500 message with no details |
| 2 | Reading `session.py` | An interrupted or failed replay left a half-written folder, and the next run then refused with a misleading "already has files" | The replay is built in `<run>.partial` and renamed only after `summary.json`, the last file, is written; a leftover `.partial` is never read as a result, blocks the next run with a clear message, and is never deleted by the program |
| 3 | `run_ml_demo.py --days 0` | No validation (and with an existing replay the argument was silently ignored) | Days must be a whole number from 5 to 250, refused before anything is written |
| 4 | Repeat runs | Every run used `run1`, so the only way to keep an earlier replay was to pick folders by hand; no way to list or choose among them | Numbered runs (`run1`, `run2`, ...), `--new`, `--list`, `--run`, a run list on `/ml`, `/ml?run=ID`; the default shows the newest readable run |
| 5 | Reading the order form | A form submitted twice (double click, back-button resubmit) traded twice | Each rendering of the form carries a one-time id; a reused or invented id is refused with a visible reason ("Not submitted: this form was already used") |
| 6 | Review of `/ml` | No risk-limit status, refusal meanings or simulator assumptions on the ML page; refusal messages absent | Added "Risk limits and refusals" (limits in force, refusals with the engine's own explanation), "Simulator assumptions", an introductory panel, navigation, run picker, clearer empty and 404 states |
| 7 | Adding screenshots | The repository safety scan fails closed on binary files, so images inside the tree make the scan test fail | Screenshots are kept outside the repository, in `../NIFTY_PaperTrading_V6_screenshots/`; the scanner was not changed |

## Already working (verified by running, not changed)

Cash, premium, fee and realised-P&L accounting (re-derived independently in the new tests); risk limits; rejected trades never become fills; unpriced positions stay unpriced; restart restores the ledger and account; provider gating fails closed; the replay audit reads CONSISTENT / FULL; reproducible replays (identical hashes on repeat runs).

## Security checks performed

* Full suite incl. `test_structure` (stdlib only, no network modules outside the two allowed places, no order or broker names, no network use) and `test_dashboard` (no credential words or order code in the dashboard source, no form or link on the non-interactive page, no URL other than loopback).
* The two tests loosened in V6-0.3 were re-read and still bind: the main page may carry exactly one link, `/ml`, and only in interactive mode (asserted as `["/ml"]`); the `--ml-dir` flag was added to the allowed command-line options, and no flag can change the host (server binds 127.0.0.1 only; other hosts refused).
* `/ml` and `/api/ml`: GET/HEAD only (POST, PUT, DELETE, PATCH give 405), Host header checked (foreign host 403), CSP `default-src 'none'` with only the hashed local script, no script or form on the page, run ids restricted to letters, digits and underscore.
* Repository safety scan: 141 files, 0 findings, 0 skipped (pattern-based; it proves nothing about the absence of secrets or order code).
* Data separation: tests assert the fixtures contain only 2031 dates, the manifest names no market source, the `ml` package reads no research or market files, research models have standing NONE and cannot trade even with parameters, and the demo model is refused on any origin other than synthetic fixture data.
