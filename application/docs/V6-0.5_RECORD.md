## Timestamp limitations (important)
- `tt` is documented only as "Today's time", type integer. The documentation's examples show it as a 10-digit **string**, and both example values (1691020800 and 1622160000) are exact multiples of 86,400, i.e. midnight UTC. That points to a day marker, not a quote or trade time. Treating it as a quote time would be wrong, and judging freshness from it would show everything as stale.
- So `tt` is stored exactly as received (`provider_time_raw`), shown on the page, and never parsed or used for freshness. `provider_time` stays empty, `time_semantics` and `latency_class` stay `UNKNOWN`.
- The local receive time (`received_at`) is our own clock when the response arrived. It is shown separately. It proves nothing about when the market observation was made, and a recent receive time does not make a price live.
- The only freshness rule applied to provider data is the local response age (30 s limit), which can turn a snapshot `STALE`. Nothing can turn it `LIVE`.
- `last_trade_time` (Groww) and `ltt` (FYERS depth) are last-trade times, not quote times; neither is used here.
- FYERS does not state in the pages read that the Standard plan's data is real-time. A support confirmation of permitted use is not such a statement.

## Dashboard states
`LIVE` (documented real-time + documented, fresh quote time), `DELAYED` (provider confirms delay), `SIMULATED` (synthetic only), `UNVERIFIED`, `STALE`, `UNAVAILABLE`.
The FYERS adapter can produce `UNVERIFIED`, `STALE` and `UNAVAILABLE` only; tests show no response, however perfect, makes it `LIVE` or `DELAYED`. Values are shown in
LIVE, DELAYED, SIMULATED and UNVERIFIED and withheld in STALE and UNAVAILABLE. The banner and the cell tags come from the snapshot itself: provider data carries its state name and
`data-synthetic="false"`, synthetic data carries `SYN` and `true`. A provider-mode dashboard that receives synthetic or unclassified data refuses it.

## Symbol resolution
Index: `NSE:NIFTY50-INDEX`. Option: you give expiry, strike and CE/PE; the program downloads the NSE_FO master and accepts the contract only if the underlying is exactly `NIFTY`, exactly one row
matches the expiry (IST date), strike and type, the ticker ends with that strike and type and starts with `NSE:NIFTY`, the details text equals the expected `NIFTY dd Mon yy strike TYPE`, the lot and tick are positive, and the expiry is not past.
Anything else stops with an error (`NOT_FOUND`, `AMBIGUOUS`, `INCONSISTENT`, `EXPIRED`, `MASTER_UNREADABLE`, `BAD_REQUEST`); nothing is guessed. Option bid/ask must be non-empty, uncrossed (bid below ask) and on the contract's tick.
A rejected option quote leaves the index visible with a note.

## Manual smoke test
```
python run_fyers_smoke.py
python run_fyers_smoke.py --option-expiry 2026-11-03 --option-strike 24000 --option-type CE
```
Run it yourself after setting `FYERS_APP_ID` and `FYERS_ACCESS_TOKEN` in that terminal. It makes one quotes request, prints state, reason, prices and the raw `tt`, never credentials or the header.
Expected on success: `state: UNVERIFIED`. Please check: that the GET host is accepted (otherwise `UNAVAILABLE` with a reason such as `FYERS rejected the credentials` or `could not reach FYERS`), that the index symbol is accepted, what `tt` looks like in a real response, and whether the numbers match your FYERS app.

## Known restrictions
- Polling on page load only, at most one upstream request per 5 s; no WebSocket (not needed for a first snapshot implementation).
- Entitlement denial can only be recognised from HTTP 403; FYERS documents no distinct code.
- Redirects are refused; proxies set in the environment are honoured by `urllib` as usual.
- The symbol master (about 16 MB) is downloaded at dashboard start when an option is requested; its date is shown at start-up.
- The structure and name tests are static checks of this source tree; the safety scan is pattern matching; neither proves absence of order code or secrets.
- This is a research display. It is not a source of fills, and the V6-0.1 eligibility boundary is deliberately not connected to it.
