# V6-0.2 implementation record: minimal local dashboard

Scope: a local, read-only browser page showing **synthetic** data, to check the interface and data flow. No real market data, broker,
model, signal, database, scheduler or authentication. Stopped after V6-0.2.

## Files
Added: `run_dashboard.py`; `src/niftypaper/dashboard/{__init__,__main__,status,sample_data,render,server}.py`; `tests/test_dashboard.py` (26 tests); this record.
Changed: `README.md` (dashboard section, test count), `docs/SAFETY.md` (dashboard section), `tests/test_structure.py` (see below).
Unchanged: every V6-0.1 source file (`quotes.py`, `eligibility.py`, `contract_specs.py`, `safety/`), config, and the other three test files.

Why `tests/test_structure.py` changed: it banned the `http` module everywhere. The dashboard server needs `http.server`, so the check now
allows `http` in `dashboard/server.py` only, and a new test asserts that no other file imports it. All other bans (socket, urllib, requests,
asyncio, and so on) are unchanged. The eligibility boundary was not touched, and the dashboard does not import it.

## Design
- `status.py`: `DataState` (SIMULATED, STALE, UNAVAILABLE), data classes, and `assess()`, which fails closed.
- `sample_data.py`: the only source of synthetic numbers (fixed, deterministic; invented `SYN-CE-24000`-style labels). Providers are callables `provider(now) -> Snapshot | None`.
- `render.py`: pure HTML/JSON rendering; values appear only in the SIMULATED state, each tagged `SYN`.
- `server.py`: `http.server`, 127.0.0.1 only, GET/HEAD only. A provider error means UNAVAILABLE, never synthetic data.
- A real-data adapter later would be a new provider plus a new state; it would not need to change the page code that withholds values.

## Dependencies
None added (`dependencies = []`). Standard library only: `http.server` (local server), `html` (escaping), `json`, `argparse`, plus modules already used.

## Known limitations
- Any program on this computer can reach the port; there is no authentication, and loopback binding is not protection from local malware or other local users.
- Host-header, CSP and method checks are basic hardening, not a security review. The tests show properties of this code as written, not complete security.
- Static checks (no forms, no order words, no network imports) cannot stop a later change that adds them; the safety scan and review are the guards.
- Synthetic numbers are fixed, not a model of any market. Staleness is only demonstrable via `--scenario stale`, since fresh synthetic data is stamped with the current time.
- The 30 s staleness limit and the example balance are placeholders. Windows-only testing; browser rendering not visually checked.
- Not done, by design: real data, adapters, V6-0.3.
